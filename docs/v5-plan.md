# TaoUi 5.0: аудит архитектуры и план мажорной версии

> Живой документ. Статус: черновик 0.1 (2026-10-27), после аудита кода 4.0.1. Ничего не реализовано.
> Все цифры ниже измерены на коммите `06fbcc3` (4.0.1), а не прикинуты на глаз.

## 0. Вердикт

Фундамент хороший, его надо сохранить:
три слоя токенов, одна шкала размеров через контекст-класс `tao-size-*`, локаль по именам пропсов, чистая логика в `src/*.ts` с тестами,
tree-shaking работает (один `TaoButton` = 18.7 КБ min / 6.4 КБ gzip, вся библиотека = 175 КБ / 50.5 КБ).
Тесты 183/183, `vue-tsc` чистый.

Слабые места все одного рода: **механизм написан в каждом компоненте отдельно, а не один раз на библиотеку**.

| Механизм | Сколько копий | Чем плохо |
|---|---|---|
| Всплывающая панель (позиция, закрытие снаружи, scroll/resize, z-index) | 8 компонентов: Popover, DropdownMenu, Select, Combobox, Date, DateRange, Tooltip, Copy | ≥4 разных алгоритма позиции, разная клавиатура, z-index литералами |
| Модальный оверлей (блок прокрутки, Esc, ловушка фокуса, Teleport) | 3: Modal, Drawer, ConfirmHost | Esc/стек слоёв не общие |
| Тон (`success`/`danger`…) | 6 компонентов, 2 стиля | у Button 29 селекторов вручную; `tone="success"` на primary/secondary **ничего не красит** |
| Иконки | 3 механизма: класс шрифта (шрифта нет), inline `<svg>` (8 компонентов), символы `✕ ‹ › ▶ ⏮ ⋮ −` (12 слотов) | нет единого вида; `▶`/`⏮` на части платформ рисуются цветным эмодзи (риск известный, здесь не проверялся) |
| Плумбинг поля формы (`inject(formFieldKey)`, invalid, describedBy) | 15 компонентов | копипаста |
| Календарь | Date и DateRange: 13 из 13 функций с одинаковыми именами | два файла на 1 логику |
| Список с клавиатурой | Select и Combobox: 8 общих функций | то же |
| Устаревшие алиасы | ≈30 пропсов/событий/токенов | сообщение обещает «удалим в 3.0»; 3.0 и 4.0 вышли и не удалили |

Обе твои задумки (палитры и меню) упираются ровно в эти места.
Поэтому предлагаю: **5.0 = «фундамент»**: сделать механизмы общими и вычистить старьё.
Палитры, меню-бар и компоненты из бэклога ложатся сверху как 5.1, 5.2, 5.x (аддитивно, без ломки).

## 1. Что подтверждено кодом

### 1.1 Всплывающие слои
- 8 файлов (3272 строки вместе), в каждом свой `updatePosition` (25–65 строк) и те же три глобальных слушателя.
- Позиция: DropdownMenu выравнивает по правому краю, Select копирует ширину триггера, Popover умеет 4 стороны с flip и clamp, Tooltip и Copy считают сами.
- Клавиатура: у Select есть Home/End и пропуск disabled; у DropdownMenu нет ни того, ни другого, нет и type-ahead.
- Esc у Popover слушается на `document` для каждого открытого окна: два вложенных закроются разом.
- z-index литералами: 1000 (Modal, Drawer), 1050 (панели), 1060 (Tooltip, Copy), 1100 (Toast), 1200 (Confirm). Токенов нет.
- Следствие для меню-бара: подменю, наведение с «безопасным треугольником», roving focus, type-ahead собрать на этой базе = девятая копия.

### 1.2 Тон и цвет
- `TaoButton`: `variant="danger"` и `tone="danger"` делают одно и то же. `tone=''` как «нет тона».
- Тон красит только `ghost` / `text` (и `secondary` только danger). `<TaoButton tone="success">` без variant выглядит как обычный accent. Документация обещает обратное.
- Лучший паттерн уже есть в Alert и Toast: класс тона выставляет одну переменную `--*-tone`, остальное из неё. Его и надо поднять до уровня библиотеки.
- Контраст accent как текста (ghost/text Button, ссылки) в **светлой теме уже сейчас ниже AA**: `#ff227a` на белом = 3.64:1, на `gray-50` = 3.34:1 (нужно 4.5). Белый на розовом primary тоже 3.64. `tests/tokens.test.ts` проверяет `*-text` статусов и `on-*` (≥3:1), а accent-как-текст не проверяет.
- Дубль токена: `--tao-color-text-on-accent` = `--tao-color-on-accent`.
- `--tao-transition-base: all …` используется в 28 местах (23 файла). `transition: all` анимирует всё подряд, в том числе `backdrop-filter` и `box-shadow` у glass-поверхностей.

### 1.3 Панели и скругления
- `TaoCard` и `TaoBlock` дублируют блок CSS поверхности; `radius = 8`, `padding = 20 / 16` зашиты числами, а не токенами (`--tao-radius-panel`). Пока так, правило «вложенные скругления» (6.6 в theming-doc) нереализуемо.
- Card имеет 9 слотов с пересекающимся смыслом: `headerTitle` (h2 по центру), `title` (тоже h2), `header` + `headerSecondary`, `sub`, `cover` + `overlay`, `footer`. В бэклоге лежат ещё `media`, `corner`, `stripe`, `closable`.

### 1.4 Локаль и SSR
- Локаль это модульный синглтон (`shallowRef` на уровне модуля). В Nuxt SSR на одном процессе локаль одного запроса протекает в другой. README заявляет Nuxt 3. Тестов на SSR нет (по коду видно, на деле не гонялось).

### 1.5 Тесты
- 41 из 67 файлов компонентов ни разу не импортируются тестами (часть покрыта косвенно: SliderBase через Slider, SegmentedOption через Segmented).
- Нет ни одного теста для Modal, Drawer, Popover, Tooltip, Combobox, Date, DateRange, Split, Carousel, то есть ровно для семейства, которое мы будем переписывать в Фазе 3.

### 1.6 Упаковка
- Tree-shaking по JS: **в порядке**, трогать не надо.
- CSS одним файлом: 133.5 КБ / 18.9 КБ gzip, независимо от того, что импортируешь. Тема `light` вшита в ядро.
- Tarball: 541 КБ (2.8 МБ распакованно). Source maps 1.56 МБ, CJS + его map 1.19 МБ. Без CJS распакованно ≈1.6 МБ.
- Нет поля `sideEffects`; пиры содержат `nuxt`, хотя библиотека его не импортирует.
- В TaoUx это уже сделано лучше: `sideEffects: ["**/*.css"]`, карта `exports` по фичам, `tests/exports.test.ts`, `scripts/consumer-smoke.mjs`. Переносим обратно.

### 1.7 Экосистема (важно для ломающих изменений)
- Мост `taoux/theme/taoui.css` наводит `--tx-*` на 11 токенов `--tao-color-*`: accent, accent-subtle, bg, surface-sunken, text, text-strong, text-muted, border, border-strong, danger, success.
- Тест моста читает `node_modules/@1337exp/taoui/src/styles/semantic.css` по пути: если файл переименуем или разобьём, тест TaoUx упадёт.
- `taofx` (потребитель): TaoButton ×50, TaoInputNumber ×35, TaoSelect ×11, TaoSwitch, TaoTooltip, TaoColorInput, **TaoTimeline ×3**, TaoSplit ×3 и ещё 11 токенов. Он же лучший приёмочный тест для 5.0.

## 2. Разбор задумок

### 2.1 Темы (`theming-architecture.md`)

Что сохраняем целиком: «стопы → роли», тёмная и светлая версии через смену ролей, автоконтраст, glass подхватывает атмосферу, правило слот / проп, правило вложенных скруглений.

Что предлагаю поправить:

1. **«Слой ролей» не новый слой.** Семантика (`semantic.css`) уже и есть роли. Палитра это **генератор перед ней** («слой 0»), компоненты по-прежнему читают только семантику. Так проще объяснить и не нужно переписывать компоненты.
2. **Ядро идеи лежит в самом конце документа**: «конвенция цвета: tone, color, переменная, слот». Это и есть механизм тона из п. 1.2. Его надо поднять наверх и сделать первым шагом.
3. **Контракт тона из трёх значений:** `fill` (заливка), `on-fill` (текст на ней), `text` (цвет как текста на странице). Сегодня он есть только у danger, и то частично. Accent тоже становится тоном и получает `accent-text`. Это сразу чинит светлую тему из п. 1.2.
4. **Роли выбирать по яркости, а не по номеру стопа.** Доказательство (контраст чёрного и белого на стопах):

   | Палитра | стоп 1 | стоп 2 | стоп 3 | стоп 4 |
   |---|---|---|---|---|
   | Marple | белый 5.3 | чёрный 6.8 | чёрный 10.9 | чёрный 15.6 |
   | Sunset | чёрный 5.8 | чёрный 8.3 | чёрный 11.2 | чёрный 15.6 |
   | Violet Dusk | белый 11.4 | белый 5.8 | чёрный 14.6 | чёрный 17.7 |

   У Sunset все 4 стопа просят чёрный текст. У Violet Dusk стоп 1 на тёмной странице даёт 1.61:1 (невидим как акцент), стоп 2 даёт 3.16:1 (годится для заливки, не для текста). Значит, в тёмном режиме акцент это стоп 3 или 2 (по ярлыку), и всё равно нужен `accent-text` отдельно. Ответ на открытый вопрос 1: ранжировать стопы по OKLCH-яркости и брать роль из окна яркости режима.
5. **Конфликт акцента и статуса: он системный.** Проверено на шести палитрах из референсов (оттенок в градусах, статусы сейчас: danger 354°, warning 43°, success 143°, info 221°):

   | Палитра | Пересекается со статусом (разница ≤25°) |
   |---|---|
   | Sunset | все 4 стопа ~ warning |
   | Marple | стопы 1–2 ~ danger, стопы 3–4 ~ warning |
   | Ocean Blue | стопы 1–2 ~ info |
   | Pinheiro | стопы 1–3 ~ success |
   | Tokyo Night | стоп 1 ~ info (слабо) |
   | «Cores» (бирюза / оранж / малина) | бирюза ~ info, оранж ~ warning, малина ~ danger |

   Следствие: у любой палитры акцент похож на какой-то статус, и кнопка `tone="warning"` в Sunset неотличима от основной. Фиксированные статусы не решают проблему (зелёный `success` будет выглядеть чужим на Tokyo Night), полностью производные тоже (в Sunset `danger` станет оранжевым).
   **Схема «привязанные статусы»:** оттенок статуса остаётся в своём коридоре (смысл узнаваем: красный, жёлтый, зелёный, синий), а яркость и насыщенность берутся из палитры, чтобы статусы выглядели той же семьёй; внутри коридора оттенок можно подвинуть к палитре. Пресет вправе переопределить любой статус вручную. Тест пресета проверяет: каждый статус отличим от акцента (разница оттенка или яркости выше порога); если нет, пресет обязан задать переопределение, иначе тест падает. Смысл всегда дублируется текстом или иконкой (правило доступности остаётся).
   Заодно из референсов видно: фон страницы это очень тёмный оттенок палитры (у Ocean тёмно-синий, у Sunset тёмно-коричневый), то есть `surface-tint` из п. 7 нужен и для самого `bg`; во всех шести референсах фон тёмный (ярких и белых фонов нет). Узоры у Pinheiro и Tokyo Night это дизайнерский концепт: фоны и картинки не наша забота, библиотека даёт только тёмный тон и свечение.
6. **Где генерировать (вопрос 3).** Производные (hover, subtle, tint) через `color-mix()` в CSS, он и так используется по всей библиотеке, новой планки браузеров не появляется. JS-хелпер `setTaoPalette(stops, mode)` для своих палитр и честного WCAG-контраста (в `color.ts` уже есть `parseColor`, `srgbToLinear`). Пресеты поставляем как статический CSS, значения зафиксированы тестом.
7. **Стопы или шкала 50–900 (вопрос 2).** Четыре стопа и производные. Шкала нужна только нейтралям (она уже есть: `gray-*`), в них подмешиваем 4–8% стопа 1 как `surface-tint`.
8. **Контраст `on-accent` (вопрос 5).** Целимся в 4.5:1; если ни чёрный, ни белый не дотягивают, берём лучший и фиксируем в тесте. Сегодняшний порог 3:1 слишком мягкий для кнопки 14px / 500.
9. **Атмосфера** (свечение фона): отдельный токен `--tao-bg-atmosphere` и класс `.tao-atmosphere`, включается явно, в `base.css` по умолчанию не лезет. Только статические градиенты, без `filter: blur` на больших площадях (в README уже есть предупреждение про glass поверх анимации).
10. **Миграция (вопрос 4)** в мажоре снимается: переименовывать можно. Но 11 токенов из п. 1.7 это публичный контракт; меняем их только вместе с TaoUx.
11. **Структура документа.** Разделы 6.5 и 6.6 (около 15 идей компонентов) не про темы. Вынести в `docs/backlog.md` и триажить отдельно, иначе theming-doc не закрыть.
12. **`TaoAnimatedBorder`** единственный литерал-цвет в библиотеке (правило 6 в CONTRIBUTING). Рекомендация: остаётся компонентом (не эффект-класс и не пакет `/effects`), получает `tone` / `colors`, `prefers-reduced-motion`, радиус из токена. Решение не срочное, 5.1.

### 2.2 Меню (`menubar-architecture.md`)

Деление «вид в TaoUi, поведение и команды в TaoUx» верное, граница TaoUx проверена (там уже есть `history`, подпути в `exports`, нет `hotkeys`/`commands`). Что добавить:

1. **Открытый вопрос 1 поставлен не там.** «Расширять `TaoDropdownMenu` или завести `TaoMenu`» вторично. Сначала нужен движок (раздел 1.1): `useFloating`, `useDismiss`, `useLayer`, `useListNav`. Потом ядро `TaoMenu` на нём, а `TaoDropdownMenu` и `TaoMenubar` становятся тонкими оболочками. Select/Combobox/Date переезжают на тот же движок.
2. **Тип данных: дискриминированное объединение вместо булевых флагов.** `separator?: boolean` и `checked?: boolean` не различают «без галочки» и «галочка снята», и нет места для `radio`-групп (роли `menuitemcheckbox` / `menuitemradio` разные).

   ```ts
   type TaoMenuItem =
     | { type?: 'item'; id: string; label: string; icon?: string; shortcut?: string; disabled?: boolean; items?: TaoMenuItem[] }
     | { type: 'checkbox'; id: string; label: string; checked: boolean; shortcut?: string; disabled?: boolean }
     | { type: 'radio'; id: string; group: string; label: string; checked: boolean; shortcut?: string; disabled?: boolean }
     | { type: 'label'; label: string }
     | { type: 'separator' };
   ```
   TaoUx объявляет структурно такой же тип у себя (без импорта TaoUi) и проверяет совместимость типовым тестом: связь остаётся «только данными».
3. **Иконки обязательны**: галочка и стрелка подменю. Без Фазы 4 меню-бар получит ещё два текстовых символа.
4. **Имя `TaoTabBar` занято по смыслу** (`TaoTabs` уже ARIA-tablist, а `TaoTabBar` это навигация). Предлагаю `TaoNav` с `layout="bar | rail | drawer"` (как в theming-doc про классы размера). Решить до 5.1.
5. **Контекстное меню** (`TaoContextMenu`) почти бесплатно на том же `TaoMenu`.
6. **Переполнение**: пункты, не влезшие по ширине, уходят в «…». Для первой версии не нужно, но API не должно ему мешать.
7. Порядок TaoUx (hotkeys, затем commands, затем `toMenu`) остаётся как в твоём документе.

## 3. Целевая архитектура

```
Слой 0  палитра (опционально, 5.1)   4 стопа + режим           ──генерирует──┐
Слой 1  примитивы                    ramps, шкалы                              │
Слой 2  семантика                    color-*, контракт тона, z-index, motion  ◄┘
          + themes/dark.css, themes/light.css (равноправные файлы, `:root` = dark)
Слой 3  контексты                    tao-size-*  tao-tone-*  tao-surface-*  tao-density-*
Слой 4  хуки компонента              --tao-button-*, … с запасным значением

Логика  composables: useFloating · useDismiss · useLayer · useListNav · useField
        чистые *.ts: slider, date, color, pinFormat … (как сейчас, с тестами)
        иконки: реестр SVG + запасной режим «класс шрифта»
```

Принцип: «контекстные классы» повторяют удачную схему `size`. Компонент читает **только** `--tao-tone-*`, `--tao-control-*`, `--tao-radius` / `--tao-pad`, не знает, откуда они взялись (тема, палитра, прямой `color`).

## 4. План по фазам

Размер: S (до пары коммитов), M, L. Фазы идут по порядку; 2 и 3 можно параллельно в двух worktree (пересекаются только токены z-index).
Каждая фаза заканчивается зелёным `type-check` + `test` + `showcase:build`. Для визуальной проверки используем уже готовый `npm run media` (скриншоты через Playwright).

### Фаза 0. Страховочная сетка (S–M), поведение не меняется
Ветка `v5`. Тесты клавиатуры и закрытия для DropdownMenu, Select, Combobox, Popover, Tooltip, Modal, Drawer, Date, DateRange. SSR-смоук: `renderToString` для всех 67 компонентов. Перенос `exports.test.ts` и `consumer-smoke.mjs` из TaoUx. Тест «публичные токены» (11 из п. 1.7). Фиксация базовых цифр из раздела 1.
**Готово, когда:** новые тесты зелёные на нетронутом коде 4.0.1.

### Фаза 1. Чистка (M, механическая)
Удалить все устаревшие алиасы (список в разделе 5), тесты «deprecated aliases still work» и «deprecation warnings», строки в README и таблицах пропсов шоукейса (тест `showcase.propTables` поймает дрейф). `deprecate.ts` оставить как инфраструктуру, но с параметром `removeIn` вместо зашитого «3.0». Снять `TaoSegmentedSize`, `--tao-field-height`, `--tao-color-text-on-accent`.
**Готово, когда:** `grep -i deprecated src` находит только `deprecate.ts`.

### Фаза 2. Токены и тон (M–L)
Файлы: `tokens/{primitives,semantic}.css`, `themes/{dark,light}.css`, `contexts/{size,tone,surface}.css`. Контракт тона `fill / on-fill / text / hover / subtle`; новые `on-success|warning|info` (правило 2 в CONTRIBUTING меняем: теперь есть компонент, которому они нужны). Accent как тон + `accent-text`. Button: `variant` ∈ primary / secondary / ghost / text, `tone` ∈ accent (по умолчанию) / neutral / success / danger / warning / info, работает на всех вариантах (29 селекторов → около 8). Alert, Tag, Toast, Avatar, Confirm на тот же механизм. Токены z-index (`--tao-z-dropdown`, `-modal`, `-toast`…). Токены transition без `all`. Контракт панели `--tao-radius` / `--tao-pad` / `--tao-radius-inner`. Тест токенов: accent-как-текст ≥4.5, каждый `on-*` ≥4.5 или зафиксированное исключение.
**Готово, когда:** `tone` работает на любом `variant`, светлая тема проходит AA, `tests/tokens.test.ts` расширен.

### Фаза 3. Движок всплывающих слоёв (L)
Спайк до одного дня: нативный `popover` (top layer) и CSS anchor positioning против JS-позиционирования с Teleport. Интерфейс composables скрывает выбор. Порядок миграции по возрастанию риска: Popover, Tooltip, Select + Combobox, Date + DateRange, DropdownMenu (в `TaoMenu`), Modal + Drawer + Confirm (через `useLayer`). `TaoMenu` с подменю, checkbox / radio, type-ahead, Home / End, пропуском disabled; `TaoDropdownMenu` получает `items: TaoMenuItem[]`.
**Готово, когда:** вне `useFloating` нет позиционирования по `getBoundingClientRect` для панелей; один обработчик Esc и клика снаружи на слой; z-index только из токенов; тесты Фазы 0 зелёные; код стал заметно короче (цель фиксируем после спайка).

### Фаза 4. Иконки (M)

Контекстное меню: якорь нулевого размера в точке клика, клавиша Menu открывает у элемента, повторный правый клик переносит меню. 22 теста (`tests/menubar.test.ts`), SSR, демо «Menubar / Context menu» в шоукейсе. Не сделано: сворачивание пунктов в «…» на узкой полосе, долгое нажатие на iOS (там нет `contextmenu`).
- **`TaoNav` (тоже в 5.0.0):** один список пунктов, три вида (`bar`, `rail`, `drawer`). `auto` сделан на container queries вместо ResizeObserver: на сервере сразу верный вид, ничего не прыгает, и верно внутри `TaoSplit`. Для этого TaoNav стал оболочкой: страница в слоте по умолчанию, раскладку (низ / бок, прилипание, безопасная зона) делает он; без слота это отдельная панель. «Ещё» с `TaoMenu` при пунктах больше `maxBarItems`. 15 тестов (`tests/nav.test.ts`), SSR, демо с рамкой переменной ширины. Попутно: всплывающие панели больше не отстают от плавной прокрутки (`absolute` в координатах документа), у всех всплывающих панелей радиус панели, у пунктов концентрический, контекстное меню закрывается при прокрутке (`closeOnScroll`), в тёмной теме `text-disabled` стал тусклее `text-muted`.
- **Плотность (тоже в 5.0.0):** вторая ось контролов поверх размера, классы `tao-density-compact | comfortable | default | auto` на любом контейнере. Размер задаёт основу (`--_tao-height` и т. п.), плотность добавку, текущие токены пересчитываются везде, где меняется любая ось (иначе класс плотности в глубине дерева не подействовал бы: переменная вычисляется там, где объявлена). comfortable 34 / 44 / 52, compact 22 / 32 / 40, auto = comfortable на `pointer: coarse`. Select и Combobox переносят плотность в телепортированные панели. Переключатель в шапке шоукейса. 8 тестов (`tests/density.test.ts`).
- **`TaoTree` (тоже в 5.0.0):** поведение живёт в самом компоненте, как у `TaoMenu`: TaoUi не может зависеть от TaoUX, поэтому `useTree` из заметки не нужен. Логика данных отдельно в `src/tree.ts` (видимые строки, единицы отметки, состояние и переключение чекбокса) и тестируется без Vue. Плоский список с `aria-level`. Модель отметок хранит узлы без детей; отмеченная ленивая папка после загрузки передаёт отметку детям. 21 тест. Иконки `tao-folder` и `tao-file`. Вне рамок: перетаскивание узлов и виртуализация.
- **`TaoChecklist` (тоже в 5.0.0):** тонкая группа над `TaoCheckbox`, как `TaoRadioGroup` над радио: fieldset, модель — отмеченные значения в порядке пунктов, «Выбрать всё» с промежуточным состоянием (недоступные пункты не трогает), счётчик с `aria-live`, зачёркивание как вид. Внутри `TaoFormField` группа берёт id поля и перекрывает контекст поля для своих чекбоксов (иначе все взяли бы один id). 10 тестов. Попутно: отметки в `TaoTree` приведены к виду `TaoCheckbox` (квадрат внутри, а не галочка), `TaoPagination` получил `pageInput`, стрелки `TaoInputNumber` — чёткую линию 1.5px.
- **`TaoTimeline` — вертикальная лента (тоже в 5.0.0):** имя старого плеера отдано ленте в том же мажоре без предупреждений (решение владельца 2026-10-28: мажор и есть разрешение, карта миграции — CHANGELOG и MIGRATION). `active` превращает ленту в прогресс, без него это журнал; `alternate` через container query. Логика состояний в `src/timeline.ts`. 9 тестов. Зачёркивание в `TaoChecklist` теперь на весь текст пункта.
- **Галочка вместо квадрата (2026-10-28):** контекст отметки (`tao-mark-*`) сделали и тут же убрали по решению владельца: квадрат внутри акцентной коробки читался как пустая рамка, выбирать между ними незачем. Отмеченный чекбокс теперь всегда с галочкой (TaoCheckbox, TaoChecklist, TaoTree), форма в процентах от коробки.
